One more authorization fix, completing the redirect saga: **`Redirect URI cannot be used in the RPC OAuth2 Authorization flow`** is gone.

## What was going on

Discord's RPC authorization has two easy-to-miss requirements that produce opposite-sounding errors:

- Your application must **have a Redirect URI registered** — without one, authorization fails with `missing "redirect_uri"` (fixed by the setup step added in v0.2.2).
- But the authorization request itself must **not name a redirect** — v0.2.2 started sending one, which Discord rejects with the error above.

v0.2.3 keeps the registration requirement (leave `http://127.0.0.1` in your app's OAuth2 → Redirects) and stops sending the parameter, matching what Discord expects on both counts.

## Upgrading

No portal changes needed if you followed the v0.2.2 instructions — just install this build, launch, and click **Authorize** once. The CouchCord panel opens on success.
