Fixes the "connected but nothing works" state: panel stuck on **"Not in a voice channel"**, buttons doing nothing (then failing late with *Closed by Discord*), no HUD — even though authorization succeeded.

## What was wrong

A message-framing bug in the RPC library's transport: its read loop requires each socket read to contain **exactly one** message. The moment Discord's replies coalesce into a single read — routine on Windows named pipes, and near-guaranteed in the burst right after authentication — incoming message processing dies permanently. Commands still reach Discord (your disconnect really disconnected you), but responses, voice events, and even Discord's keepalive pings are never seen again, so Discord drops the connection about a minute later.

CouchCord now installs a corrected transport read loop (proper incremental frame parsing) in place of the library's. Verified offline against a scripted Discord endpoint that deliberately coalesces frames: the stock transport reproduces the exact field symptoms; the fixed one completes the session with channel and members intact.

## Also in this build

- **Request timeouts**: any RPC call that gets no answer within 10 seconds now fails visibly in `couchcord.log` and triggers a clean reconnect — a stalled pipe can never again look like "buttons that silently do nothing."

## Upgrading

Install over your current version and launch. No Discord portal changes needed. Expect: authorization already cached (no popup), the HUD appears if you're in a voice channel, mute/deafen/switch/disconnect respond immediately.
